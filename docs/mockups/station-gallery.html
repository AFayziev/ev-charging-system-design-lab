How this maps to the API

  • Each file: POST /stations/{id}/media/photo-uploads with galleryVersion, contentType, byteLength → signed PUT URL bound to that exact type and size.
  • Browser PUTs bytes straight to storage (XHR for progress), then POST …/{itemId}/upload-completion. The tile moves to Processing and polls the editor query until Published or Failed.
  • Every write sends galleryVersion. A 409 conflict refetches the editor and retries once; uploads start one at a time so concurrent starts don't conflict with each other.
  • Replace sends replacesItemId. The current photo stays visible to drivers until the replacement is published; a failed replacement keeps it.
  • Failure text is chosen from failureCode / problem code, never from message text.
